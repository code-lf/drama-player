# LangGraph 真实业务接入进展（2026-10-23）

## 本批交付范围

本批是第一批中的**阶段收集真实接入**，不是统一生成全流程完成。双视频计划、逐项报价、批次费用授权、两条任务派发及结果恢复均尚未接通，仍不得宣称可一次提交两条。

### 已实现

- 新增 `skill_stage_runtime.py`：真实阶段 API 调用 LangGraph，图通过确定性校验节点及 `interrupt` 等待字段保存/整组提交。局部字段保存不调用模型，完整提交才通过 `requirements_ready` 门禁。
- 新增显式迁移 `20261023_0098_skill_graph`，在独立 `skill_graph` schema 建检查点表与索引；请求、读取、健康检查均不自动建表。
- 运行 JSON 的 `orchestration` 固定引擎、图版本、技能版本和阶段修订。只在显式新建阶段时选择引擎；已有阶段不自动迁移。关闭开关不把已固定的图运行降级为旧执行器。
- 阶段图借用 SQLAlchemy 当前 PostgreSQL 连接和事务，显式同步写 checkpoint；业务答案、幂等收据、最后请求号、状态投影和 checkpoint 一起提交/回滚。连接由原连接池归还，不另建常驻池。
- 同一运行行锁串行接收字段修改；提交携带预期修订与稳定请求号；旧请求重试返回当前已保存结果，不倒退图。JSONB 键顺序不用于推断最后命令。
- `advance` 服务层增加图门禁；图错误返回明确 503 并回滚，不自动回退旧执行器或调用供应商。
- 新增只读 `/api/healthz/skill-graph`，检查迁移版本；不开图、不恢复许可、不提交任务。

### 原子事务边界

目前只有无外部副作用的阶段收集节点使用上述短事务，节点不会等待模型、视频生成或供应商请求。它直接避免阶段答案和 checkpoint 的跨库提交缺口。

**这不是付费任务 outbox 的替代实现。** 后续分析、报价、费用授权与媒体提交尚未迁入图；其业务命令/待派发记录仍需独立设计事务与可重试派发，不能在当前事务中加入耗时网络调用，也不能据此宣称任务重启不重复扣费已验收。
