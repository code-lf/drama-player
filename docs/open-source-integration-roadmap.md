# Livliv 开源复用与全链路开发路线

更新：2026-10-29。适用：用户端 `ai-create-video`、API `ai-create-video-api`、管理端 `ai-create-video-admin-web`。

## 1. 长期开发原则

以尽快交付可靠的商业产品为目标：**能直接使用的成熟组件优先使用，能适配的优先适配，只有差异化需求或复用成本更高时才自研。**不为了“自研率”保留劣于开源的实现，也不为了“引入框架”重写已可靠的业务底座。

本文件是后续功能开发的选型与验收入口，不是所有接入均已完成的声明。每次开发先查现有代码、当前验收记录和[决策台账](open-source-decisions.md)，更新受影响条目，不重新进行无结论的大范围选型。

- 优先级：已有可靠实现 > 满足条件的成熟组件 > 小范围适配 > 自研通用引擎。
- 比较总成本：接入、兼容、安全、测试、升级维护、回滚，而非只比较代码行数和演示效果。
- 开源方案在正确性、安全和商用条件达标后，能缩短交付周期就采用；不要求必须优于所有维度。
- 不以旧投入作为保留理由；也不以知名度、星数、作者身份作为生产安全证明。
- 一处完成一处验收。单元测试、真实引擎文件检查、真实页面、供应商采购四类证据分开记录。
- 本次交付文档不安装依赖、不升级运行环境、不采购媒体、不提交 Git、不部署。

## 3. 全链路架构：复用底座，替换薄弱执行模块

```text
用户对话 / 技能制造机 / 画布
                ↓
业务命令入口：账号、草稿修订、稳定请求号、资源权限
                ↓
Agent 适配层：技能读取、资源读取、文字创作、受控工具循环
  ├─ 现有受控创作实现（兼容旧运行）
  └─ Deep Agents（优先接入验证；通过后用于指定新运行）
                ↓
LangGraph：编排、等待、恢复；业务数据库：任务/费用/结果权威来源
                ↓
现有计划 → 真实报价 → 用户确认 → 现有媒体任务 → Celery
                ↓
片段与声音选择 → 合成计划 → 可替换媒体引擎 → 文件检查 → 平台存储
                ↓
返回成片、来源引用和可继续编辑的计划
```

框架负责“如何持续工作”，模型负责“理解与创作”，业务服务负责“允许做什么及收费”，媒体引擎负责“实际编码”。任何一层都不能靠模型文字声称另一层已完成。

不另建用户、账本、作品库、任务状态或第二套外层流程编排。Deep Agents 内部执行状态可由其 runtime 管理，但平台只投影明确的业务操作与引用；不能让外层和内层分别重试同一采购。

## 4. 已确定的选型方向

| 组件 | 决策 | 接入范围 | 不接管的部分 |
| --- | --- | --- | --- |
| LangGraph + PostgreSQL checkpoint | 保留 | 原业务编排及新 Agent 的集成边界 | 不把 checkpoint 当账本 |
| Deep Agents SDK | 优先动手做隔离接入，不停留在调研；通过门槛后小范围启用 | 制造机连续工具修改，随后是技能使用 Agent | 不替换草稿、权限、报价、任务与画布；不强制购买托管服务 |
| MoneyPrinterTurbo | 优先评估可复用执行模块，不仅停留于看 README | 后续配音、字幕、配乐与合成的具体模块/编排经验 | 不导入整套 WebUI、账号、任务状态、素材下载和供应商默认采购链 |
| VideoAgent | 视频分析/蒸馏需求进入时再做专项验证 | 有证据的镜头分析、自然语言编辑工具 | 不作为当前制造机或基础合成的前置依赖 |
| ComfyUI | 当前不引入 | 将来确有自部署模型需求时重评 | 不是现有 Vue Flow 画布或模型 API 的必要替代品 |
| FFmpeg / 已有媒体库 | 保留并核对具体构建许可 | 编码、裁切、拼接、混音；也可被新适配器复用 | 不自行开发编码器；不把第三方模型/音乐授权包含在代码许可里 |

“优先接入”不等于未经安全/兼容验证直接生产启用；“已有代码保留”不等于拒绝更成熟的引擎替换。

## 5. 第一批：Python 升级与 Deep Agents 真正接入

### 5.1 环境升级先做，不把 3.10 当借口

本次查阅的 Deep Agents 主分支包元数据为 0.7.32、Python >=3.11，仍有 Beta 分类；这只是选型时间点快照，不是已批准的生产锁定版本。

1. 优先以 Python 3.12 建立独立候选虚拟环境；若原依赖不兼容，再验证 3.11 并记录具体原因。不要直接覆盖 `.venv` 或先升级整个运行主机。
2. 在候选环境解析、固定依赖，核验 LangGraph/checkpointer、数据库驱动、Celery、AV/Pillow、FFmpeg 包装、支付及供应商 SDK。不能只验证 Deep Agents 能 import。
3. 运行相关后端与原业务回归、真实数据库隔离测试、API 与 Worker 冒烟，确认当前任务快照和原图版本可读。
4. 升级 Python 本身不应改业务表或价格。需要迁移时另列明确的增量迁移与审批，不因安装框架批量重写数据。
5. 通过后，更新项目 Python 声明/锁文件/启动说明/CI 和 Worker 运行路径；记录原环境回退方式。独立进程服务不是默认方案，避免为省代码增加一套微服务运维。

### 5.2 技能创作助手接入

先使用一个 Agent，不默认增加多个子 Agent。新增一层内部适配入口即可，不提前拆成庞大的通用插件平台。

- 仍从原命令服务接收所有者、草稿、预期修订和稳定请求号，接受记录先持久化。
- 首批工具按需包装现有服务：读最新草稿、读授权文本资源、查真实能力目录、提交受控修改候选、校验技能、生成步骤转换候选。
- 工具名称是待注册的内部契约，不在文档中编造 Oii 的 `active_step` 等已接通入口。
- 多轮工具调用先在一次命令的暂存候选中工作；发布前整体校验并核对原修订。保留原有候选核对，不恢复用户已删除的顶部巨大技术字段预览。
- Agent 只能访问本人授权草稿与资源的受控视图；不直接把服务器目录、用户上传文件夹或全库技能路径挂进可写文件系统。
- 默认不提供 shell、任意 Python、任意 URL 抓取、任意 MCP、删除文件和媒体采购能力。技能文档、附件和资源均不能增加工具权限。
- 默认关闭未批准的遥测/追踪外传；模型调用仍只发送本次授权内容，日志不保存密钥、完整私有文件或思考正文。
- 每个命令限制轮数、工具次数、总时间、模型 token/费用预算和上下文大小；具体值由样例验证确定，配置项加中文注释。超限明确结束，不无限自我修复。
- 供应商工具调用、结构化输出、流式事件和思考参数分别验证；框架不代替模型能力。记录实际模型与真实思考阶段，不声称能查看或展示内部推理。
- 事件显示真实的工具开始、结果、校验及终态摘要；不把预设阶段卡伪装成逐次调用日志。UI 只展示必要的用户说明和摘要。

### 5.3 对照样例与采用门槛

固定相同输入、模型、资源与评审标准，对比旧实现和候选 Agent；记录每次样本，失败也保留。不使用付费媒体验证文字 Agent。

| 样例 | 必须验证 |
| --- | --- |
| 60秒软件宣传文案策划 | 实际口播模板、综合分镜表、独立视频提示词、同一时间预算、真实UI/概念视觉分支，不擅自生成媒体 |
| 双版本商品广告 | 两条完整独立方案；用户只改一条时不丢另一条；规格、素材和卖点已知不重问 |
| 图片创作技能 | 完整输入/构图/提示词/事实约束；不套软件宣传模板 |
| 局部优化与检查 | 只改要求部分，检查不修改；文档、元数据、资源的一致性真实核对 |
| 文档转步骤 | 按真实能力和稳定ID生成候选，模型/风格保留；不把未接通阶段伪装可执行 |

门槛：关键样例内容通过；越权/越界工具不能执行；冲突不覆盖；同请求不重复应用；中断和迟到有明确终态；真实页面可用；成本/时延/接入成本有记录。达到正确性和安全要求且总体能节省交付成本，就采用，不要求每次回复都更快。

若 Deep Agents 不适配当前供应商或依赖，不反复搭完整平行系统：记录失败原因，只比较一个轻量替代方案——在现有 LangGraph 内复用工具调用构件实现受控循环。不得同时推进两套生产 Agent。每轮验证结束必须形成采用/缩小范围/不采用的决定与证据，不能无限调研。

## 6. 第二批：从技能试用到实际创作

在创作助手可用后优先完成，不先扩充高级工具。

1. 保留草稿冻结试用、不可变版本与个人私有范围；试用不生成正式版本，不授权媒体费用。
2. 把步骤合同实际接入原收集、策划、计划服务；新 Agent 只组织调用，服务端校验模型与固定风格，不能丢绑定。
3. 本批先通收集/策划 + 一组同类图片或视频，视频可继续已有合成。文字策划技能可只交文档，不强制制造媒体任务。
4. 当前“最多一个媒体阶段”是本站尚未接通的范围，不是 LangGraph/Deep Agents 的技术上限。先完成该子集，再逐项扩为跨媒体，不能永久以门禁替代开发。
5. MD 与步骤共用业务合同；建议与强制约束分开。正文改后标记步骤需核对，转换先确认，不静默覆盖。
6. 用同一技能依次完成创建、局部修改、刷新、完成/再次编辑、冻结试用、收集、策划、真实报价和结果定位；多条需求完整保留。
7. 用户端与后台共用服务及指导版本；后台只由管理员显式保存系统新版本，默认停用，不自动改历史运行。
8. 业务已提交但图未 checkpoint：按原请求/业务引用恢复，不换执行器重新提交。成功项不重做；未知项先对账。

旧运行固定原引擎和合同；旧命令不自动切入新 Agent。关闭新入口不删除旧结果；回滚不能把不兼容的新运行静默交给旧执行器，应保留读取并明确恢复条件。

## 7. 第三批：成片与声音，既不迷信自研，也不盲搬

用户当前要求先解决技能；本节是沿技能使用验收到后期时执行的计划，不是现在另开音轨扩项。

### 7.1 对比实际执行，不比较仓库名气

现有合成器已使用 FFmpeg，不是自研编码器；MoneyPrinterTurbo 的视频服务使用 MoviePy、字幕及音频组合等模块，依然需要适配其配置/模型类型/文件处理依赖。现有实现是否更快、对方是否更成熟，都不能仅凭源码长度或 README 判定。

使用已授权、已完成素材与本地合成测试数据；对比双方的最小可复用路径，不购买新视频，不导入示例音乐或未经授权音色。

| 场景 | 比较内容 |
| --- | --- |
| 异构多段视频 | 顺序、裁切、横竖屏策略、帧率、有效画面时长、原声/静音兼容 |
| 旁白 + BGM | 用户选择/取消、入点、裁切、音量、可懂度、削波、时长不足时明确失败或提示 |
| 配音输出 | 模型及音色真实可用、试听授权、真实时长；不把文本预算当录音时长 |
| 字幕（启用前单列范围） | 时间戳来源、中文换行、字体许可、漏字、与录音对齐；不提前承诺精准口型 |
| 运行成本 | 同硬件/预设/输入的耗时、CPU、内存、进程清理、依赖与部署复杂度 |
| 异常 | 缺素材、损坏音轨、Worker中断、重复投递；不交付不完整文件，不重购上游成功片段 |

每个样例记命令/锁定版本/输入摘要/参数/输出检查和播放证据。短样本与较长样本都要覆盖，不能只拿小色块编码成绩推断真实产品视频性能。

### 7.2 按对照结果作选择

- 现有裁切拼接通过且更轻：保留；成熟开源音频/字幕模块适配成本更低：直接复用该模块。
- 若开源渲染路径整体更符合本版要求：替换 `ShortVideoComposer` 后面的执行实现，不重写 `VideoCompositionJob`、权限和平台存储。
- 不直接把整个 `task.py` 或 WebUI 搬进来；优先使用独立包或最小模块。确需复制源码，保存上游 commit、文件清单、许可证、改动补丁及升级说明。
- 禁止盲装两个项目的全部依赖；VideoAgent 的固定旧版 FastAPI/Pydantic、重型推理依赖也不能直接覆盖现有 API 环境。
- 不默认以网络抓取服务或免登录 TTS 作为商业配音保障；供应商、音色、配额、内容政策和商业权益逐项核对。

### 7.3 最终业务闭环

用户可选择仅片段或成片，选择保留原声/已有旁白/生成配音、无BGM/已有BGM/生成音乐。未接通的选项不能伪装可用。生成声音前分别展示真实方案与费用，用户授权后才创建对应任务；声音失败不重做视频。

合成读取固定的已完成资产及时间轴，返回成片同时保留片段、音轨、技能版本和可编辑合成计划；重新生成某片段不改写旧作品，受影响成片由用户确认更新。读取、刷新、试听已有文件不重新采购。

跨媒体自动垫图、配音、音乐、字幕逐项接入原任务服务；只对当前已接通且验收的阶段开放。保留用户选择与真实确认，不能凭“全自动”之名跳过授权。

## 8. 商业许可与安全：快接入的必要底线

维护方身份、代码许可、依赖许可、模型权重、服务条款、素材权益和运行安全分别核对。MIT 允许商业使用但有保留声明等条件，并不提供质量/安全担保；GPL 不等于禁止商用，复制/修改/分发方式须专门判断，不能承诺一个服务隔离方案自动消除义务。

引入前至少记录：

1. 仓库、准确包/模块、版本或 commit、来源校验、维护方、许可证原文和第三方声明。
2. 依赖清单/SBOM、直接及传递依赖漏洞、安装脚本、网络请求、插件执行和高危能力；高风险未解决不得开放给用户。
3. 素材/模型/音色/字体各自权益；MoneyPrinterTurbo 的附带音乐不能因仓库 MIT 就视为可商用。
4. 上传与模型输入按账号隔离；受控文件解析，限制路径、URL、重定向、协议、文件大小、解码资源和运行时间。
5. 私有素材、提示词、日志、追踪服务的外传范围及配置；不自动启用云端追踪。
6. 金额、权限、素材归属和稳定请求号始终由现有服务检查；模型提出操作不等于执行授权。
7. 备份/回退、版本升级影响和旧运行兼容。正式开放前必要的法务复核不能由开发文档冒充完成。

“先用后打磨”允许界面细节、模板覆盖和可选工具逐步优化；不允许把越权、重复扣费、素材侵权、原稿丢失留到以后。

## 9. 后续每项功能的固定工作法

每个新增功能/明显返工在台账补一条简短决策；小样式修复复用既有决策，无需重做框架调研。

```text
需求与可验收结果：
现有入口/代码/证据，真实缺口：
已有组件/开源候选，拟复用的具体部分：
许可证/安全/依赖兼容结论：
最小验证、成本与停止条件：
采用/局部适配/自研理由，禁止改动范围：
新旧协议、状态归属、回滚方式：
代码/接口/真实文件/真实页面/付费验收分别的证据：
剩余问题、下一步、负责人：
```

- 默认一次只验证一个优先候选；没有合适候选才扩大搜索，不重新争论已定且条件未变的选型。
- 先通一条垂直链路再扩功能，不一边换框架一边重做整个 UI、所有技能和全部后期。
- 主控负责跨端合同、安全和最终验收；独立小任务可按用户授权派给 `livliv (2)`（`01a16725-14d3-79b1-ae68-788b32d33e7e`），明确文件边界、禁改范围和证据要求，不同时编辑同一文件。不另建同名会话。
- 服务启动检查原启动说明及实际进程；真实页面验收必须先有 API、Worker、队列与登录后页面，不用“端口已开”代替。
- 状态统一为：待验证、已实现待验、已实测、阻塞/不采用。页面显示与业务执行各自记录，不写笼统“全部通过”。
- 不写无证据的完成百分比或时间承诺。每轮按完成门槛交付进展、剩余风险和下一项。

## 10. 执行顺序与完成门槛

2026-10-30执行优先级补充：按用户最新决定，先以人工核对的标准技能从画布走通实际使用，再将验证过的技能规范反向用于制造机产出。A至E的完成门槛全部保留，不再仅以制造机MD长度推进；声音与合成沿同一条业务链验收，不另开平行项目。当前画布新Agent仅在候选环境指定新运行中验证，正常页面默认配置未切换。

| 批次 | 交付 | 通过后做什么 |
| --- | --- | --- |
| A | 新 Python 环境兼容、Deep Agents 最小受控工具实现、固定样例对照和决策 | 通过则锁定版本，在指定新草稿使用；否则明确替代，不长期双轨开发 |
| B | 制造机连续修改/资源/步骤转换、自动保存、冲突恢复、用户端与后台接线 | 创建→核对→刷新→完成/试用可操作，不仅生成Markdown |
| C | 技能运行接入原计划/核价/确认/结果，受支持步骤不再整体拒绝 | 一项纯文字、一项图片计划、一项多视频计划分开验收；采购另取授权 |
| D | 实际技能链路到达后，合成执行对照与最小声音流程 | 选择声音→保存→合成→播放→刷新；引擎取更合适者，不保护旧自研 |
| E | 有明确需求时扩视频分析蒸馏/跨媒体自动串联/高级字幕工具 | 单独评估 VideoAgent 等，不能倒过来阻塞首版 |

完成标准：内容样例、真实工具记录、MD/步骤合同、草稿/版本/权限、费用确认、重复/迟到/重启恢复、用户端与后台、桌面与手机页面分别有证据。不能以“框架已安装”“工具卡有勾”“文件生成”替代用户可用。

现有业务结果优先复用；付费视频仍按用户剩余授权核对，未授权不新增采购。当前不改短剧、不批量迁移旧技能、不自动公开个人资源。
