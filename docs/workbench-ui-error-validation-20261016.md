# 工作台菜单、遮挡与错误链路验证

## 范围

- 添加素材菜单修复图标 span 被正文 flex 拉伸的问题；菜单宽度 260px。
- 模型菜单宽度 320px，顶部三类等宽 Tab、固定居中图标、两行省略文字；不新增假开关。
- 图片区按工具与产物栏真实高度留出空间，工具不再挤压覆盖图片。
- 历史批次接口补充已脱敏错误码和原因；图片、视频对话优先显示真实失败原因。
- 工作台图片仅对明确失败且可恢复的错误自动尝试，含首次最多十次，持久化次数与失败任务关联。同批次只扣一次，最终失败沿用原退款链路；审核和参数错误不自动改写重提。视频与音频没有新增自动重生成。

## 验证边界

- 使用已有白猫、癞蛤蟆作品检查，无额外收费生成。
- 首轮真实浏览器：模型弹层实测宽 320px、图标容器 32px；100% 图片底边 507.98px，工具顶部 515.98px，间距 8px；产物栏在说明下方。
- 后端隔离覆盖十次总上限、恢复后剩余次数、安全审核与参数拒绝、未知状态不重提、正常重试成功及历史错误字段恢复。
- 实际模型重试、重复扣点及退款未触发线上收费任务验收；隔离测试不能等同真实计费验收。
- 构建保留已有大包、依赖导出弃用及 ES2019 BigInt 提示。
- 本轮结果：前端回归 78/78，后端创作及相关接口回归 152/152，生产构建通过。错误提示真实计算样式为 12px、rgb(161,161,170)。
- 多个开发标签在构建后一起恢复请求，验证时触发已有频率限制；没有放宽限流，也没有把 0 积分的读取失败占位当作真实余额。
- 最终真实浏览器检查：1440×900、1920×1080 及 600×900 的模型菜单无横向溢出，图片／视频／音频 Tab 正常切换；1920 下 100% 与 150% 缩放时工具与可见图片边缘均相距 8px。验证截图见 `output/workbench-model-menu-20261016.jpg`。

- 任务已提交显示居中紧凑通知卡、绿色勾选图标，文字为“任务已提交 · 右侧查看进度”；仅真实排队或运行状态显示，不将未知状态或失败标绿。

- 前端回归 80/80，构建通过。没有提交新生成任务，提交卡真实运行中的显示未通过收费任务验证。

## 繁忙终态与状态同步核查

- 原任务状态接口确认返回 failed，错误外层码 generation_failed、reason=service_busy、upstream_code=RateLimitReached。原分类遗漏 reason；现合并稳定分类字段，繁忙进入已确认失败重试白名单，遵守返回的 retry_after。
- 本地通用任务进程曾退出，原任务数据库停在 processing；恢复缺失 API／通用 Worker，并只查询原任务收敛失败状态。没有重新发起图片请求。
- 状态查询异常进入 status_unavailable，画布显示“正在同步任务状态”，继续有限退避查询，不把旧百分比当作实时进度，也不把查询异常当作任务失败后重提。
- 前端 81 项回归、后端图片及错误链路 54 项回归通过；真实新生成／自动重试未发起。
- 功能模型核查：工作台商品图读取主模型和允许模型；fallback_model_ids 未进入该执行链，短剧资产另有兜底链路。本次未静默切换工作台模型，避免破坏已确认报价快照。

## 刷新恢复限流修复

- 实际日志确认活动与图片历史 GET 返回 429，原生成任务没有因刷新而取消。数据库中上一轮有 executed_request 和媒体绑定，最新一轮为新的未执行 ready 方案，不按外观把两轮合并或改写历史。
- 关闭 ofetch 隐式重试；任务状态读取收到 429 后冷却一分钟，保留原任务并继续查询，手动刷新不绕过冷却。维护查询的 focus 和定时器共享 30 秒冷却。
- 任务同步失败仅更新对应任务状态，不再写入另一轮方案确认卡使用的全局错误。未重放生成，未新增扣点，没有放宽后端限流。
- 验证：82 项前端回归及生产构建通过；独立浏览器标签刷新后恢复原会话、两项旧产物、任务状态及最新审核失败提示，不再停在同步中。截图 `output/refresh-recovery-20261016.jpg`；未点击确认或发送。运行中旧 Worker 的十次策略不因前端刷新而热更新。
