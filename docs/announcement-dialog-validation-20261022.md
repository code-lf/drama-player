# 登录后公告弹窗修复与验收（2026-10-22）

## 原因与改动

- 原全局公告在挂载时无条件请求公开目录，展示条件未判断登录，导致游客也看到右上角气泡。
- 原关闭记录仅使用公告编号，未区分账号和内容版本；切换账号也未隔离在途响应。
- 改为完整登录态才请求和展示，换号／退出清空列表并使旧请求失效。
- 使用现有 LivDialog settings dark：居中、最大560px、24px圆角、磨砂遮罩、正文独立滚动、全部公告及知道了按钮。不新增基础弹窗组件。
- 每次加载只提示一条；关闭按账号和公告内容版本保存，不写成已读，不连环弹出下一条。版本有变化可以再次提醒。
- 不可关闭公告遵守现有运营配置；LivDialog 新增可选 dismissible，默认true，其他调用保持原行为。
- 全部公告页面不叠加自动弹窗，顶部铃铛仍直达公告时间线；全站维护拦截保持独立，不因普通公告登录限制而失效。

## 验证结果

- 12项测试通过：游客零请求、登录读取、退出／换号迟到响应、账号与版本隔离、关闭不假写已读、不可关闭配置、时间线分页、安全动作链接及Vue模板编译。
- Nuxt生产构建通过；未部署、未提交Git，未修改公告发布数据、账号及历史已读数据。
- 真实浏览器游客状态：1440×900与1920×1080检查，公告气泡不再出现，短剧入口正常展示。截图 `.codex-runtime/announcement-guest-1440-20261022.jpg`。
- 用户手动登录后，真实浏览器发现 liv-ui 自动组件名包含目录前缀，补充显式导入 LivDialog／LivButton，并增加编译绑定断言，防止只通过模板编译却在运行时渲染成自定义标签。
- 登录后实屏通过：1440×900和1920×1080均为560px宽、24px圆角、居中磨砂弹窗；390px宽视口测得358px弹窗、左右各16px。正文容器计算样式为overflow-y:auto。当前真实公告仅含短正文，未伪造长文或修改公告数据，长正文实际滚动尚未实测。
