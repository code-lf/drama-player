# 短剧双界面、单生产链路

目标是现有表单页面与画布操作不同，但读写同一个项目、确认剧本快照、资产档案、镜头和成片。保留现有画布 Agent 的路由、对话和工具循环，不把 Agent 当作生产状态数据库。

当前差距：自由画布把文稿与提取结果保存在会话草稿中；旧短剧生产按项目及已确认剧本版本操作。提取编号不是资产档案编号，不能按名称自动关联。旧资产 GET 会补建视觉基准并编译档案，不能直接挂到画布刷新上当纯读接口。

原链路没有 Deep Agents 不代表执行不可靠：持久化、资产锁定、核价和异步执行都应该保留。缺的是对话层的阶段判断、跨步骤上下文和受控工具反馈。新链路应让现有 Agent 负责理解与编排，两种界面仍调用同一个确定性服务执行写操作，保留旧结构解析、视觉基准和素材约束提示词。

首页「短剧」选择标准模式或画布模式；标准模式仍进入原剧本输入和分阶段工作台，画布模式打开现有创作画布，不自动创建生产任务。从画布内开始制作不再询问界面模式。画布打开后可绑定已有短剧项目，独立会话并不等于已建立生产项目。

故事、广告后续复用分镜、素材版本及合成能力，但保留各自的交付类型、提示词与校验条件，不为复用分镜强制建立短剧项目。本轮不开放尚未接通的跨类型分镜入口。

画布共享生产接口现同时读取标准工作台当前分镜方案；不经过带有历史状态修复的项目详情聚合。分镜按集显示固定卡片，保留真实镜头 ID、顺序和同项目同账号预演图；无图则占位。画布可显式刷新生产资料，不生成任务、不写分镜。分镜编辑、视频选版和按集合成仍待接通。

## 2026-11-09 首批：正式剧本交接

- 画布剧本详情新增「短剧制作项目」。打开只读；显式确认后，`POST /creation/sessions/{session_id}/production-intake` 按会话稳定键与已保存文稿修订，调用原短剧建项和导入逻辑。主项目、短剧记录、剧本写入和会话关联在同一事务提交。制作要求独立保存在关联收据，不拼入剧本。重复请求返回原项目；已存在项目不因改稿或改参数而覆盖。原剧本导入上限仍为 20,000 字，超限拒绝，不截断画布原文。
- 画布可以直接打开同一正式项目的标准工作台。正式剧本确认后仍使用既有显式绑定核对生产快照；暂未自动将导入收据升级为生产绑定。草稿提取不进入生产资产表。
- 分镜路由改调共用 `submit_storyboard_plan`，提交事务后按原范围投递 Worker，现有标准路由与响应不变。现有分镜服务分段提交版本、积分和运行记录；画布收费写入须先补跨入口请求收据、报价快照与投递未知状态核对。本批未接通画布分镜提交或后台自动续跑。

待登记为阶段技能的现有专业资源：剧本对应 `script_structure`、`script_review`、`global_review`；资产对应 `asset_production_extract` 和角色、场景、道具的提取／视觉模板及资产编译器；分镜对应原导演总图、分场、镜头修复与质检模板。迁移时保留模板、编译、结构化合同与局部修复规则，实际 Worker 消费后记录版本，不能把目录清单当作技能已执行。

## 正式剧本确认与资产报价

- 「短剧制作项目」可按需读取正式原文及版本，并经原短剧确认服务锁定；画布额外核对关联、文稿修订、基础解析与正式结构令牌。旧确认不覆盖新版，不把已有生产项目退回资产阶段。原文变更后无法证明与基础解析匹配，或正式版本与活动制作版本不一致时，画布拒绝静默切换。
- 确认后可显式调用原资产提炼报价。它可以按旧工作台规则初始化本地资产档案，但不会调用模型、扣费或入队；报价返回前再次核对正式版本。报价不是授权，本批没有新增执行入口。
- 「核对基础解析」只读恢复原结构节点，或展示待确认的真实报价；明确确认后才走原解析队列。旧报价核对原文、画幅、分辨率、风格、模型和预计积分，任何变化须重新报价。标准、画布的同一解析运行共用首节点投递收据，回执未知不会自动重发。文本块、运行、节点和项目状态一次提交。
- 正式确认不自动改绑，资产报价初始化后可使用原显式绑定读取资产及分镜。资产提炼收费提交、分镜到成片及 Agent 自动接续仍待接入；本批未实际调用供应商或 Broker。

## 资产提炼确认（增量）

## 镜头选版与按集成片

## 首帧预演与画布回填

- 画布白名单新项目可为当前集分镜准备首帧，整批核对画幅、真实静态文件、镜头指导及已绑定素材版本；确认前不提交，投递回执未知只读核对。测试 Worker 独立任务名，没有真实生图或扣费分支；旧 Worker 不能接管样本，标准页面仍保留原预演操作。

- 画布直接导入的新项目与手动关联的已有项目都可回填共享生产资料。分镜显示预演状态和测试样本标记；首帧收据完成后只刷新生产资料，不提交新任务。
- 隔离 PostgreSQL 使用真实 Redis 测试专用队列及 Python 3.12 Celery Worker，验证首帧受理、回填与去重；测试不会订阅原通用队列。该证据不代替正式会话的真实模型与剧本到成片整链验收。

迁移顺序：

1. 为会话和项目建立显式、可核权的关联，冻结剧本修订与项目确认快照，禁止同名自动合并或静默覆盖。
2. 画布读同一资产工作区的已提交快照，使用选中资产版本的图片和状态；旧路由维持原响应，兼容初始化与读取分离。
3. 画布动作和 Agent 工具复用原上传、提示词确认、报价及执行合同，不能经工具绕过费用许可。执行结果仍写原生产表。
4. 同样接通分镜与成片；通过两个入口对同一项目读取、修改和刷新验证一致性，并覆盖越权、换稿与重复确认。

当前已完成四列四行版式和显式绑定：从画布新增菜单选择「绑定短剧项目」，复用原项目目录，核对确认剧本版本及资产数量后再保存。会话接口 `production-workspace` 的 PUT 核对画布文稿修订、项目归属、确认快照及生产版本；GET 直接读取既有生产资料，不启动初始化或模型。绑定独立于布局，任一侧换版须显式重新确认。读取失败不把独立提取结果冒充共享数据。绑定弹窗尚未做真实浏览器验收。
