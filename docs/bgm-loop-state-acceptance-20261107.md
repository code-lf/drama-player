# 短 BGM 循环与状态同步验收（2026-11-07）

## 范围与结论

本轮补齐五项对应实现，不换框架、不换长音乐掩盖失败，不重放历史未知任务、不采购新图片、视频或音乐。功能实现及原失败素材复验已完成；下文分别标注自动回归、页面与文件证据，未验项不称通过。

## 具体改动

1. 音轨新增 `repeat_mode=none|loop`、`play_duration_ms`。源 `trim_start_ms/trim_end_ms` 与目标铺设长度分开；loop 只允许 BGM，必须明确目标长度，旁白不得循环。无循环默认保持旧合同序列化与幂等指纹。
2. 准备及创建合成均核验权限、固定文件身份和实际解码容量。不能只信元数据时长。源区间越界在确认前返回 `AUDIO_SOURCE_RANGE_EXCEEDED` 与字段路径、实际时长；Agent 取得结构化修正反馈，首次加一次修正，不反复无限重试。
3. FFmpeg 在固定源截取后使用 48kHz 原速循环，裁至目标长度，再设置音量及起点；没有变速。确认摘要说明原声、音量、循环和最终时长。
4. 图片／视频报价 pending 无执行批次时仍只读轮询；只接收同一运行、修订、报价身份的更新，不覆盖手动编辑。服务端自动回填与新输入隔离，提交清空不删除下一条新输入，真实云端冲突不绕过。
5. 历史卡按运行身份同步终态，完成时间优先于残留 planning；失败停止加载及累计用时。提供“修正合成”填入复用现有素材的修正请求，不自动发送、不重建上游素材或采购。
