# 自由创作技能路由与首批技能完善 · 2026-11-05

## 本轮实现范围

自由创作是路由，不是默认图片提示词。沿用 Python 3.12.11、Deep Agents 0.7.32、LangGraph 和原业务服务，不安装另一套 Agent 框架，不引入新的任务、账本或文件执行系统。

| 层 | 具体内容 | 当前接线 |
| --- | --- | --- |
| 自由创作 | 理解原文、最新修改、历史回答、主动参数、素材与业务进度；模型按当前目标选技能 | `free-router/SKILL.md`，仅平台 free 创作入口开放路由工具，普通聊天/文本节点不开放 |
| 基础助理 | 图片创作助理、视频创作助理、音乐创作助理 | 目录元信息 → 受控读取完整指导 → 按需读取方法资源 → 原结构化交付 |
| 首批专项 | 商品主图、海报设计、图片修改、图片转视频、商品展示 | 各自独立指导与方法资源；手选保持原技能，自由入口可选择符合执行边界的已上架技能 |
| 确认与生成 | 原图片/视频批次、音乐参数、真实报价与最终确认 | 路由和读指导不创建媒体任务、不授权费用；继续不是收费授权 |

技能目录：相邻 API 仓库 `app/resources/skills/`。原稿是原创中文内容，没有复制 Oii 私有提示词或引入其品牌。

## 选型与调用方式

复用已安装的 [Deep Agents SkillsMiddleware](https://reference.langchain.com/python/deepagents/middleware/skills/SkillsMiddleware)，依据[官方源码](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/middleware/skills.py)的渐进披露设计：先摘要、后正文、再资源。本地分发包版本 `0.7.32`、许可元数据 `MIT`；本轮没有安装或升级依赖，不代表重新完成全部传递依赖安全审计。

原生 `SkillsMiddleware + StateBackend` 只读取本轮授权目录的**内存元信息**。没有挂载宿主文件系统；`read_file`、shell、脚本、任意子 Agent 工具继续被原 Boundary 拦截。

1. 服务端从有效平台目录准备名称、用途、目标和版本；不在本地用关键词决定应选哪个技能。
2. 模型可查看 `list_creation_skills`；原生发现层已给摘要时可以直接选择。
3. `read_creation_skill` 核验本人运行、平台 free 入口、planning 状态和已上架目录，读取固定版本完整指导，保存私有快照。
4. `read_resource` 只接受根技能或当前所选技能已经登记的准确文本资源名；图片仍走既有视觉通道，文件名不代表已看图。
5. 模型按具体技能编写方案，完整用户上下文仍交给结构化生成调用，不由 instruction 摘要代替原话。
6. 结构化结果核验目标、必要素材及模型范围后，交原服务保存、报价、等待最终执行确认。不会因为调用了技能而自动采购。

这是同一受控 Agent 使用不同技能指导，不冒充已经启动多个独立子 Agent。根技能和执行器没有被悄悄更换。复杂流程、固定平台素材依赖或不允许 free 入口的技能，不通过这个简化入口冒充已完整接通，仍走其原入口。

每份均写明必要补问、已知不重问、用户可见说明、现有任务交付和能力边界。不同技能不强制共用同一套标题。基础助理和 5 个专项共 8 份技能正文、8 份方法资源，另有自由路由正文。旧临时 `quick-image-v1.md` 已并入这套目录并移除，不再给个人 free 基础技能统一叠生图模板。

默认直达带真实规格/积分的最终任务确认；只有用户明确要求先审创意或真正有取舍才先审方案。模型参数、选模理由可正常展示，不显示内部核价成功日志；不声明未实际生成的作品完成。

## 版本、权限与事务

- 新内置指导取代旧自动模板中的无条件问卷；已发布配置的补充要求保留。运营手写 Markdown 和个人原稿不被覆盖。
- 新运行冻结指南；同轮切换后返回使用首次读取版本。没有批量改写历史运行、已发布技能数据库版本或旧媒体提示词。
- 元信息缓存不授权读取任意技能、未上架技能、其他人的草稿或磁盘路径。读取没有采购、脚本及互联网执行能力。
- 目录与指导使用短事务；先释放原规划事务行锁，再在本人运行锁内核对状态并保存快照，避免等待自己的长事务。迟到读取不能覆盖已停止状态。
- 用户停止未提交方案后移除对应待确认展示；已提交批次停止接口拒绝撤销，已有文件与任务保留。状态来源以业务 `stop_record` 为准，不能单凭 cancelled 就断言用户点击停止。
