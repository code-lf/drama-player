# 文本助理、平台技能检索与手选技能边界 · 2026-11-06

## 本轮改动

继续复用现有 Deep Agents 0.7.32 原生技能发现和受控读取工具，不增加框架、Agent、任务服务或费用通道。

- 新增 `text-assistant/SKILL.md` 与 `text-assistant/writing-method.md`，位于相邻 API 仓库 `app/resources/skills/`。
- 自由创作现有四个基础助理：文本、图片、视频、音乐；不是只能选基础助理，也可从当前已上架、允许 free 入口且已接通直接执行的平台代理技能中选择。
- `list_creation_skills` 增加可选 query，按公开名称、用途等元信息检索；检索词由模型提供，不在本地解析用户原话或硬编码匹配创作类型。空 query 查看全部，未命中如实返回，不伪称找到模板。
- 用户手选的专项/个人技能仍固定原版本及自有资源，不开放自动改派目录工具；专心按该技能执行。需要别的能力时解释边界或询问，不能擅自切回自由创作。

复杂工作流、固定平台素材或不允许当前入口的技能，仍不能只读文档就当作可从 free 执行。本轮没有解除这类执行边界，也没有声称平台全部技能已支持互相嵌套调用。

## 文本交付

文本助理覆盖宣传文本、广告标题、社媒文案、邮件、口播/脚本、翻译和润色，按用户实际用途组织成稿，不固定要求所有任务输出同一套标题。

实际成稿使用既有 `reply + artifact_title`，复用文稿保存和画布文本产物。普通聊天不标成文稿。纯文字不查询无关媒体模型、不创建媒体 proposal 或媒体报价确认；文字模型仍沿用原调用、审计与用量规则，不承诺文字一律免费。

文本助理误交媒体 proposal 时，在调用正文模型前返回交付类型错误；没有先读任何技能的独立文稿交付，会交回 Agent 读取适用指导。缺真正必要信息才提问，已知信息不重复问。

参考案例只借鉴表达结构：未提供材质、耐候性、承重、挂绳、价格、折扣、库存等信息时不能自行添加；不能写完虚构卖点后再笼统说“请核实”。海外用途不自动等于特定国家/语言；双语、平台政策与限制以实际需求和已核对来源为准。

最终 API 专项 **129 项通过**（64.46 秒），包含本轮新增项与原技能、媒体结果、确认边界回归，不累加中途重复运行。2 个受影响 API 模块 Python 编译通过。

| 原生技能循环 | 发现文本助理 → 读取指导/方法资源 → 交付完整文字成果；未读取媒体目录、无媒体参数/计划 |
