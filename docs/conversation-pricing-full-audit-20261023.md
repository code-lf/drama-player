# 罐装饮品广告会话与 Mini 采购预算核查

## 核查结论

这次不是用户操作问题。会话原文、助手方案、执行需求与业务任务数量没有形成一致合同；历史整理稿还会进入后续上下文放大错误。音乐入口上轮仅统一页签，漏了类型筛选。不能将上述链路称为完整技能闭环。

## 1. 选项回答后来源误报

已定位前端 acceptAssistantPlan 的重复比较：第一次核对本轮有效素材，第二次却比较回答草稿中的已发送素材与已清空的编辑器附件。后者可在素材未改变时误拦截。

本次移除第二次附件比较，保留文字与技能变化检查；第一次改为固定版本、用途、顺序与裁切区间的规范化比较。null/undefined 与预览名称不算来源改变，替换、移除、裁切依然失效。尚未通过真实付费会话复测，不伪称所有“来源改变”路径均已修复。

## 2. 一条被恢复为三条

数据库已确认：用户新轮次写“生成 1 段”，该轮 generation_prompt、task_input.prompt 与 card 仍写 3 段。后续“这个模型再生成”继承了错误整理稿，继续承诺三段。

对应 Grok 与 Mini 业务任务实际各为一个十秒任务、一个结果，记录积分分别为 20 和 34，不是三个独立任务。文本写三段并不会创建三个任务。不能把单条结果说成完成三段交付。

本次新增直接视频执行合同校验：明确的多条视频需求不得进入单条任务；提示词增加最新用户数量优先要求，历史上下文另存 user_request，与助手整理稿 request 分离。已执行历史任务、作品、积分记录不修改，不重提、不退款。该修复是防止错交付，不等于多版本计划已开发完成；也不保证仅凭提示词就能消除所有模型理解错误。

## 3. 确认卡延迟

四轮文字响应总耗时分别约 20.4、20.2、21.1、17.5 秒；首段正文约在请求后 11.7～15.0 秒到达。卡片需要有效方案及真实报价，不能提前展示可确认的空价格卡。

已修复的来源误拦截会导致方案出来后仍无报价，属于额外卡点。历史记录没有独立的“报价开始/结束”耗时，不能把全部延迟归因于报价接口，也不能声称本次已完成性能优化。后续需给方案就绪、准备、报价、确认卡展示分别加耗时，再定位素材解析、目录读取或主线程阻塞；不以假进度掩盖模型耗时。

## 4. 对话记忆如何保存

- PostgreSQL creation_skill_runs 保存账号/会话归属、技能编号与固定版本、原始草稿、问题答案、助手卡片、完整执行需求、父轮次、运行状态和调用计时。
- 显式续作链 requirement_context 保留最近八个父轮次片段，原来 request 优先取父轮次 generation_prompt，所以助手的错误数量可能被当作后续依据。新增 user_request 留存真实输入，不把整理稿当用户确认事实。
- 旧兼容路径可读最近十二条 CreationMessage 与八个运行；是否使用该路径由运行是否已有 requirement_context 决定，并非所有历史全量都进模型。
- 个人草稿与会话执行记录是两种存储；输入框清空不应删除已发送上下文，历史也不是模型永远记住的全量长期记忆。当前未接通全量向量记忆、结构化最终需求总账或 LangGraph PostgreSQL checkpoint。

## 5. 技能确实参与，但闭环未完成

四轮均绑定 custom-commerce-ad-storyboard 第 7 版（营销分镜短片），运行保存的指导正文长度约 1246 字符，并提供给文字模型。参考图固定版本也随任务保存。

专业提示词被使用不代表流程已实现：该技能实际仍走共享助手→单条视频执行器，没有三个版本逐项编辑、逐项报价与逐项真实任务绑定；本轮也没有专业知识库读取事件或阶段识别报告核对。不能声称已读外站风格库。

## 6. Mini 四档完整预算口径

账号目录原币为 USD/百万 total_tokens；480P 与 720P 使用同样的 Token 单价。本站换算汇率为 7。

| 分辨率 | 参考视频 | 原币/百万Token | 人民币/百万Token | 示例Token | 示例总采购预算 | 折算/输出秒 |
|---|---|---:|---:|---:|---:|---:|
| 480P | 无 | $1.88806 | ¥13.21642 | 100440 | ¥1.327457 | ¥0.132746 |
| 480P | 有 | $1.149254 | ¥8.044778 | 170748 | ¥1.373630 | ¥0.137363 |
| 720P | 无 | $1.88806 | ¥13.21642 | 216000 | ¥2.854747 | ¥0.285475 |
| 720P | 有 | $1.149254 | ¥8.044778 | 367200 | ¥2.954042 | ¥0.295404 |

统一示例：16:9、输出十秒；“有”额外按两秒参考视频，并应用当前已登记的最低 Token 估算表。这里是估算，不是实际账单。

约 8 元和 13 元不是多少秒的进价，而是每百万 Token 的单价。输入视频档虽然 Token 单价更低，但示例计量更多，故总预算接近。

官网截图 ¥12.65 与 ¥7.7 由同一美元单价反推约使用 6.7 汇率；本站使用 7。官网的低至秒价与本站“十秒输出+两秒输入+最低用量”的参考条件也不相同，不能直接拿两个不同示例的平均秒价相减后判定单价错误。公开页也说明实际价格可能随账号分组及活动不同。

参考：https://toapis.cn/pricing；https://docs.toapis.cn/docs/cn/api-reference/videos/seedance/pricing.md 。后者本次直接 HTTP 读取成功，样例资料仍须与 Mini 真实 usage 账单持续核对；不得把官方参考表当每次任务的固定消耗。

本次未修改汇率、采购单价、售价或历史费用。价格界面仍需强化原币/人民币/Token与示例总价的分区，尤其“含输入视频”必须展示输入秒数和最低用量依据。
