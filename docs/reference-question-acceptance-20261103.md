## 根因与修复

- 原上传复用全局输入附件并自动回答，图片残留输入框；独立问题改为上传/保存/确认三段，刷新只恢复本人固定版本。API 增加 `reference_submission` 明确标记，校验当前题型及真实图片权限，避免确认被当闲聊回滚。
- 同一运行在补充回答前后各执行一次框架，重复开场不等于重复采购。显示保留真实读取收据，后续读取标为“沿用技能指导”；不删除实际失败。处理中工具卡与通用思考加载互斥。
- 视频结构化合同曾错误要求无关 `mv_lyrics`，供应商返回 null 被拒；图片/视频合同移除该字段，音乐保留。常量字段改等价单值 enum，交付失败要求修正字段而非退回普通回复。
- 输出预算曾按每次最大请求额累计，即便已返回小结果也耗尽；有完整可信用量才结算实际输出，无用量/断线保守保留预留。并未提高迭代次数、费用授权或输出总上限。
- 续作必需进度由运行时复用原只读工具先加载，真实记录开始/返回，交给模型使用，不再先生成后撞缺进度门禁。
- “整理1条4秒视频待确认方案”漏识别数量；补上明确视频方案中的时长修饰，保留否定句和问题/风格数量排除测试。
- 上传图不是已生成镜头。逐条来源支持 `reference:<固定版本号>`，只允许本轮已授权引用；无图片成果的上传场景向结构化模型提供真实版本枚举。未放开任意版本、URL或外部镜头编号。
