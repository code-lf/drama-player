# 镜头方案开源借鉴说明

本文记录 Livliv 镜头方案重构所参考的开源项目、实际采用内容、未采用内容和对应实现位置。原则是借鉴可验证的专业结构，不照搬项目 UI、提示词原文或不适合商业产品的技术架构。

## 已实现结果

| 借鉴方向 | Livliv 当前结果 |
|---|---|
| 单镜头叙事任务 | 每个镜头先确定唯一叙事任务、当前事件边界、转折和可检查的结束状态 |
| 动态时间编排 | 不再按段落数量平均切秒；对白、动作爆发、揭示和反应会获得不同时间权重 |
| 导演语言 | 段落保存叙事功能、景别、机位、镜头感受、节奏、表演、声音和转折 |
| 连续性 | 保存人物方位、视线、光线、服装、道具状态及交给下一段的连续性锚点 |
| 资产上下文 | 角色、场景、道具、声音和来源剧情按职责进入镜头上下文，不再无差别堆入 Prompt |
| 版本与失效 | 调优产生新方案；已有视频不被覆盖，输入变化后旧素材可精确标记过期 |
| 前端编辑 | 工作台可直接查看和编辑上述导演字段，快速切换镜头与段落操作均使用统一组件 |

本地确定性测试中，一个总时长 6 秒、原本机械等分的三段方案会按事件密度重新分配为 `1784ms / 2169ms / 2047ms`，总时长仍严格等于 `6000ms`。这只是校验样例，实际结果由每段对白、动作、揭示、反应和文本密度共同决定。

## 1. Emily2040/seedance-2.0

仓库：https://github.com/Emily2040/seedance-2.0

已采用：

- 每条视频只承担一个清晰叙事任务，并形成“开始状态、可见行动、结束状态”。
- 将剧情区分为此前发生、当前必须发生、留给后续、当前禁止提前出现，避免镜头泄漏后续事件。
- 导演判断增加镜头功能、唯一转折、观众共情对象、权力关系和潜台词。
- 抽象情绪必须转译为眼神、呼吸、手部动作、身体重心和说话节奏等可见表演。
- 机位、运镜、调度、表演、声音和剪辑落点共同服务一个导演意图。

落地位置：

- `ai-create-video-api/app/prompts/drama/storyboard_generate/system_v1.txt`
- `ai-create-video-api/app/prompts/drama/storyboard_shot_tune/system_v1.txt`

未采用：

- 不把完整方法论原文直接暴露给用户。
- 不让模型自由决定业务工作流，仍由现有固定后端链路编排。

## 2. HKUDS/ViMax

仓库：https://github.com/HKUDS/ViMax

已采用：

- 为每个导演段落补充可检查的结束画面 `endpoint`。
- 连续性锚点包含屏幕方向、视线、光线、服装和道具状态。
- 高风险镜头要求同时表达起始画面与结束画面。
- 参考素材按身份、场景、道具、运动和结束状态划分职责，避免无差别塞图。

落地位置：

- 导演段落 `extra` 契约与提示词。
- 现有 `StoryboardReferenceBindingDTO` 和 `StoryboardClipContractDTO`。

未采用：

- 不引入该项目完整的多智能体和训练流程。
- 第一版不在用户端展示复杂参考图选择树。

## 3. Forget-C/Jellyfish

仓库：https://github.com/Forget-C/Jellyfish

已采用：

- 镜头进入生成前必须具备结构化准备状态。
- 生成上下文统一包含来源剧情、动作节拍、前后镜头目标、连续性指导、构图锚点、对白和绑定资产。
- 资产、对白、基础语义和导演段落均可独立检查是否就绪。

落地位置：

- `StoryboardContextCompiler`
- `StoryboardClipContractDTO`
- 镜头工作台的来源、资产、连续性和声音意图模块。

未采用：

- 不复制其后端实体和接口命名。
- 不在当前阶段引入独立字幕、配音和合成时间线。

## 4. ArcReel/ArcReel

仓库：https://github.com/ArcReel/ArcReel

已采用：

- 每次视频生成创建新 take，不覆盖已有版本。
- 方案或提示内容改变后，已生成素材需要标记为过期或创建新版本。
- 关键道具状态跟随镜头保存，供连续性检查使用。
- 批量更新按镜头原子化处理，失败可以局部重试。

落地位置：

- `storyboard_takes`
- `storyboard_plan_versions`
- `storyboard_video_batches`
- 镜头方案版本和连续性数据。

未采用：

- 不引入自由 Agent 编排。
- 不采用浏览器端音画合成。

## 5. liangdabiao/Seedance2-Storyboard-Generator

仓库：https://github.com/liangdabiao/Seedance2-Storyboard-Generator

已采用：

- 资产使用明确的角色、场景、道具职责。
- 声音拆分为对白、环境声和动作音效。
- 高风险镜头才生成关键预演画面，普通镜头使用锁定资产作为方案参考。
- 延续镜头优先保留上一镜头结束状态。

落地位置：

- `audio_intent`
- `StoryboardReferenceBindingDTO`
- 关键镜头预演策略和连续性检查。

未采用：

- 未采用固定 `0-3 秒 / 3-6 秒` 的等分时间模板。
- 未把每条镜头都强制生成封面，避免无意义点数消耗。

## 6. gracech0322-cmd/seedance-2-prompt-library

仓库：https://github.com/gracech0322-cmd/seedance-2-prompt-library

已采用：

- 镜头描述拆分为景别、机位、运镜、速度、动作、转场和连续性。
- 每个段落限制一种主运镜，复杂组合最多三种。
- 时间段只在事件变化处切换，不按数学平均分段。

落地位置：

- 导演段落 `extra.camera_angle`、`extra.lens_feel`、`extra.pace`。
- 分镜生成和单镜头智能调优提示词。

## 7. HenryZ838978/Seedance2.0-Storyboard-Planner

仓库：https://github.com/HenryZ838978/Seedance2.0-Storyboard-Planner

已采用：

- 参考素材按首帧、尾帧、角色、场景、机位、风格、运动和声音区分用途。
- 复杂运镜组合数量受控。

未采用：

- 未采用简单叠加运镜、速度、情绪、风格和灯光形容词的“提示词优化”方式。
- 未将其静态表单直接复制到 Livliv 工作台。

## 8. 本地确定性兜底

当旧项目没有结构化导演段落时，后端会从旧 `action_desc` 构建兼容段落：

- 根据对白、动作爆发、信息揭示、人物反应和文本密度计算时长权重。
- 保证每段拥有最小可辨识时间，并精确覆盖镜头总时长。
- 自动补充叙事功能、节奏、进入方式和离开方式。
- 禁止再使用“总时长除以段落数量”的机械平均切秒。

实现位置：

- `ai-create-video-api/app/services/storyboard_workspace_service.py`
