# 我的项目统一目录（2026-10-17）

## 产品行为

- 我的项目不再把“会话”与“项目”分成上下两块。自由创作（包括纯讨论和图片／视频／音乐）与短剧共用卡片、列表、分页与分类入口。
- 分类为全部／自由创作／短剧，在服务端分页前执行。搜索、状态与排序仍处理当前页，保留明确说明；短剧原状态、进度函数和业务接口不变。
- 新建项目首先提供自由创作，也可进入短剧专业流程，不点击即创建空短剧。关联项目默认继续最近对话，同时提供进入短剧制作；没有会话的短剧仍进入原流程。
- 纯聊天不显示完成度。封面只来自本人已完成的图片结果、视频真实结果封面、音乐封面；缺失时用统一默认封面，不使用上传参考图或视频模板冒充作品。
- 左侧最近列表和顶部最近浮层均称“最近项目”，读取同一目录，首批十条、更多加载；重命名／删除后刷新目录实例，换号和卸载隔离迟到响应。

## 接口与兼容

- 新增鉴权只读接口 `GET /api/creation/projects?limit=20&offset=0&kind=all`。`limit` 为 1～100，`offset` 非负，`kind` 为 all／creation／drama；返回 items、total、offset、limit。
- 卡片返回带类型前缀的 id、kind、title、cover_url、updated_at、created_at、sessions（会话 id／title）和 drama（原短剧卡片结构，非短剧为 null）。前端保留真实 projectId，不能把目录 id 或会话 id 传给短剧删除。
- 以真实消息 `task_type=drama` 和公开 project_id 建立只读关联，核对会话、短剧与主项目两端所有权。不按标题、技能或入口猜测关系。
- 同一短剧关联多个会话只出一张卡，保留所有对话入口；同一会话创建多个短剧，每份短剧各一张卡并保留返回该会话的入口。失效／越权绑定不吞掉自己的会话。
- SQL 先关联去重，统一按更新时间与类型／ID 稳定排序再分页；不拼接一页短剧和前一百条会话，不修改底层数据，不增加迁移。
- 批量管理及删除继续使用原短剧接口和明确二次确认；对话及独立媒体作品保留。短剧删除后，仍存在的关联会话可以作为自由创作重新出现在目录。自由创作删除本轮未新增，不伪造删除成功，也不借用短剧删除接口。
