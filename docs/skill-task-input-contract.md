# 技能文档与任务输入契约

## 原则

保留 FastAPI、Pydantic、SQLAlchemy、Celery；不引入新 Agent 框架。技能文档是专业指导，不是代码、工具权限或收费授权。旧剧本、歌词原文及独立工具继续使用原业务链。

## SKILL.md 模板

```markdown
# 技能名称
## 适用范围
目标用户、场景与交付物。
## 所需输入与素材
必要信息和固定素材；未读取内容不得宣称理解。
## 澄清规则
只问缺失的关键问题，一轮一个；闲聊不强推生成。
## 交互步骤
理解需求 → 补充信息 → 整理方案 → 真实报价 → 用户确认。
## 结构化产出要求
reply：普通回复；question：必要澄清；proposal：完整方案。
proposal.generation_prompt：整合主体、场景、风格、最新修改、已回答约束与排除项。
## 工具能力与限制
只使用平台开放执行器；不执行附件脚本、任意 URL 或绕过收费确认。
## 质量检查
检查内容完整性、固定素材、模型与规格兼容性。
## 示例
描述输入、澄清与完整方案，不将确认短句当成生成描述。
```

平台与个人技能版本仍不可变。编辑器提供文档输入及空文档模板按钮，已有内容不自动覆盖。导入继续接受 `liv-skill-v1` JSON 或 `liv-skill-json` 块，其中 `skill.config.document` 保存上述 Markdown；不把任意 Markdown 当可执行配置。

## 数据流

- 原聊天保留在 `draft.original_prompt`；完整执行语义保存为 `generation_prompt`；技能前后缀编译后保存为 `draft.prompt`。三者不可混用。
- 流程 JSON 的 `task_input` v1 包含修订号、完整描述、产物类型、执行技能及版本、参数、固定素材。Pydantic 校验普通回复、问题、提案和任务输入；超长或非法结果明确失败，不静默截断执行需求。
- 参数优先级：最新明确修改 → 已确认规格 → 技能默认。规格提取只读取用户原话中的明确比例、竖图、清晰度、数量、时长和质量，以及真实目录中写明的模型；不从助手展示正文猜测参数。未识别表达可通过参数控件明确设置再报价。
- 准备接口核验本人有效流程及精确需求、素材、技能版本；完整 `execution_input` 在报价前持久化。报价签名携带修订和执行摘要指纹，重报价修改输入即撤销旧许可。已有报价、确认、计费幂等链保留。
- 图片工作台实际编译使用签名校验后的完整 `prompt`，旧独立工具继续优先其 `source_prompt`；视频和音乐继续使用经准备的 `draft.prompt`。
- 历史仅有完整 `generation_prompt` 时兼容生成新快照；没有完整需求的历史待确认方案要求重新整理。已完成任务不回写、不自动重生成。
- 助手审计记录任务输入与指纹；绑定任务时保存消息标识、任务标识及执行指纹，结合原媒体审计可定位实际出站描述。不保存密钥。

## 技能配置、公共能力与固定素材（2026-10-17）

- `/creation/catalog.capabilities` 将平台真实能力与当前技能执行目标分开；自由创作可生成图片、视频、音乐，专项跨媒体必须明确切换。音乐引擎继续使用操作及原报价服务，不混入普通模型列表，不自动附加 MV。
- 平台配置新增 `references`，缺省为空，绑定平台已发布的固定素材版本；个人技能兼容旧顶层引用并合并去重。总计最多 12 项；形成任务快照前合并，准备及提交重新校验状态，不能用旧签名绕过下架。
- 技能 `material_health` 为动态读取结果，不修改历史版本。平台素材 `/admin/library/{id}/dependencies` 列出当前技能依赖；有依赖的取消发布／归档必须显式传 `confirm_dependencies=true`。已提交任务、已完成作品和旧版本不删除，固定版本不意味着永久授权。
- 后台编辑只传受控字段，服务端合并保留旧版本未知字段及未识别的旧默认参数；不允许请求新增任意工具地址。文档修订自动生成，普通保存不自动把旧文档、前后置约束及步骤互相迁移；显式迁移遵守下面的新版本契约。

## Markdown 编译模式与平台批量迁移（2026-10-17）

- `SkillConfig.guidance_mode` 为 legacy／markdown，历史缺省为 legacy。新模式保留旧文字字段作只读来源，但实际文字只从 document 读取；旧客户端漏传模式时继承当前版本，不允许直接降回 legacy 或修改只读旧规则。
- 文档二级章节“生成前补充”“生成后约束”各最多一节，内部只能有一个完整 text 围栏。迁移使用足够长的动态反引号围栏，原有换行、标题和代码片段原样保存；损坏、重复章节或超长明确失败。其它 Markdown 是专业指导，不执行代码、HTML 或工具地址。
- 助手读取专业指导部分，不再另加载旧 workflow_steps。问题可受控返回 kind=text／single／multiple／reference，保留原多选等展示能力，不授予执行权限。历史已开始流程仍固定原技能版本和步骤。
- 准备阶段统一编译“精确前补充＋完整语义＋精确后约束”，重复预估不重复拼接。短剧原文和自定义歌词继续使用原有 raw 模式，不插入摄影等文字；真实模型、素材、报价、许可和幂等边界不变。
- 个人技能仍继承固定基础版本，未标记个人配置保持 legacy。由迁移后的平台复制到原个人编辑器时，导出为等价兼容配方：使用当前生效的精确章节作为前后缀，专业指导作为正文，避免个人前缀编辑失效；不回写已有个人版本。
- `scripts.migrate_skill_markdown` 默认只预检并输出完整备份。显式 apply 对全部启停平台技能按版本锁定、单事务发布；失败整批回滚，幂等重试不增版本。verify 核对原历史版本、当前配置、启停与排序；rollback 新增恢复版本，遇到后续人工修改拒绝覆盖。
- 旧字段缺省的 references／defaults 按既有保存服务规范化为空列表／字典；引用仍按版本规范化去重。这不修改原历史记录，迁移清单校验只对这些明确缺省做规范化，不能忽略其它差异。初始化种子跳过已迁移平台版本。

## 不在本次范围

不修改两万字符剧本上限、不接入十万字主流程、不迁移导演／资产／分镜模型客户端、不重做技能制造机。

## 新建平台技能（2026-10-17）

- `POST /admin/creation-skills` 创建 `custom-` 前缀独立技能，`executor_code` 仅允许已有内置执行器，强制 Markdown；编码冲突返回 409。新配方复用原执行服务、报价、签名与许可，不增加模型或任意工具权限。后台默认停用，启用由发布设置显式控制。
- 配方 `id/code/platform_code` 是独立版本身份，`base_code/executor_code` 表示真实执行器；准备、任务快照及签名沿用后者的工具投影，最新参数限制仍读取该独立平台配方，不能借基础能力绕过停用或收紧。发布后执行器不可更换。
- 老配置缺省 `executor_code` 等同原内置编码；不回写历史版本。个人技能保留其平台基础编号并使用真实执行器，不把新平台编号误当未接入工具。迁移预检容纳合法自建 Markdown 技能，不再要求平台目录只能有固定十八条。
- `material_health.items` 提供固定公共引用名称、版本及状态，用于编辑器跨页定位；不回传私人条目或素材正文，不构成生成授权。
