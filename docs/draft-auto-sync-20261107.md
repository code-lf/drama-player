# 输入框草稿自动同步修复

2026-11-07，范围仅为创作输入框草稿，不涉及剪辑稿、画布布局、任务或采购。

- 不重叠字段按共同基线自动合并；正文与结构化段落、引用与名称、技能与参数分别成组，避免错配。
- 同字段分歧按最后成功保存者优先。覆盖前以账号/会话隔离的独立 localStorage recovery 键保存双方完整副本。副本写入失败不覆盖；持续并发最多重试一次，保留候选并报告同步失败，不无限争写。
- 同账号同会话通过 BroadcastChannel 只发送更新通知，实际内容仍经授权接口读取。页面重新聚焦也会核对；输入中不被迟到响应覆盖。
- 恢复副本目前为浏览器本地恢复数据，尚无面向用户的版本恢复入口，不等于服务端永久版本历史。

验证：`node --test tests/creation-draft-ready.test.mjs`，16 项通过。实际查看 localhost:3000 中会话 40208183-ea08-4094-b360-d4d873332b0b 的页面，可访问性树中已无“草稿与其他页面有冲突”及选版本按钮，原对话、输入框和画布仍存在。未执行生成，也未改变历史任务。真实双标签同时编辑及故障存储场景尚未浏览器复验；不将单页面核查冒充完整协同验收。

没有安装依赖、提交 Git 或部署。

## 2026-11-08 续验

- 自动测试新增两个独立组合函数共用修订服务的场景：同字段竞争保留双方恢复副本；正文与模型参数分别修改后均被保存。专项共18项通过，不等于真实后端并发测试。
- 真实在应用内浏览器打开同一会话第二页：A输入“同步验收A（不发送）”，B收到；B修改为“同步验收B（不发送）”，A收到。
- 两页面快速分别输入“并发验收A/B”，页面最终均显示B版本，没有选版本提示。这是快速连续UI操作，不宣称制造了服务端同时写入。
- 结束前恢复原本空白输入框，核对另一页也为空，关闭临时第二页，未发送消息、生成或采购。
- 浏览器模拟断网、存储不可用、完整独立字段UI操作尚未验收；已有自动测试覆盖不替代对应浏览器证据。
