# 软件宣传片创作方法

## 事实先于表现

软件名称、功能、实际操作、权益和效率数据来自用户确认或其授权素材。没有证据时只写用户痛点与概念化解决思路，不能编造“提升十倍”“全程无需人工”等效果。

已确认的CTA、界面文字和功能名称逐字保留，不擅自换成近义营销文案。比如用户确认“了解功能”，不能在结尾、画面和提示词中悄悄改成“了解更多”。

## 叙事结构

可按痛点、方案亮相、操作演示、价值与行动组织；按目标时长和已有卖点分配，而不是强制每条都四段或六段。留出阅读、呼吸与转场时间。一次只有一个主要视觉动作，避免复杂UI文字交互。

## 视听表

每行写时间范围、叙事目的、完整口播、实际或概念素材、景别、主体动作、运镜、首尾状态和声音建议。预估字数按扣除停顿后的时间计算；真实录音后才核对实际时长。

口播密度与“口播宣传片”目标相称：先说明预计语速和停顿，不用大量无解释的空白填满目标秒数。字数估计明确称估计；没有实际计数工具或录音证据，不能声称完成机器字数审计或精确配音对齐。局部修改只调整指定段落，保留其余完整稿。

## 提示词组成

主体及来源、场景、光线风格、主体动作、运镜、首尾状态、已确认规格、应避免的变化。真实UI优先使用授权录屏/截图；概念UI不得被描述为真实产品功能。每条提示词自包含，不用“同上”代替内容。

## 媒体与声音

从当前真实模型规格拆分制作片段，叙事结构不是采购清单。BGM情绪、是否人声、配音语言和音色由用户选择；推荐不等于授权。只有实际完成并检查的文件才能作为合成来源。
