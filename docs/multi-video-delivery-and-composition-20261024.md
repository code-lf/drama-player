# 普通技能：多视频交付与轻量短片合成

## 范围及真实进度

本轮不修改短剧/导演流程，不启用旧画布。双视频只是多视频计划的首个验收样例，不将条目数硬编码为二。当前内容合同上限为 12 条，是现阶段保护限制，不宣称无限数量；超出时明确提示，不能截断。

已实现方案编辑、选择、逐项预算、刷新恢复。2026-10-24 追加内部执行准备清单：固定完整输入、技能版本、逐项预算及价格配置指纹，同运行/修订/条目使用确定请求编号。修改计划清除旧准备。准备不是费用授权、任务提交或锁价，未开放批次确认执行。此次相关后端回归 79 项通过，后续小改需复测。

## 三种交付语义

| 用户需要 | 结构 | 执行路径 |
| --- | --- | --- |
| 多条独立广告 | N 个成片，每个可以是单次生成 | 普通技能计划、逐项任务、分别交付 |
| 几个片段合成一个短片 | 1 个成片、N 个有序片段 | 普通技能计划、片段任务、轻量后期任务 |
| 长视频/复杂剧情规划 | 现有剧情、角色、分集和镜头结构 | 保留现有短剧/导演流程，不在本轮改动 |

数据必须分开保存成片数量、每片片段数量、单次模型产出数。多个独立成片也允许各自拥有多个片段，不能把三个片段误记为三条广告。路由不能仅根据秒数判断；用户明确交付意图优先，含糊时只补问这一个区别。

## 无画布的轻量合成方案

采用声明式合成清单与列表卡，不引入节点连线或自由画布。前端在方案内显示片段顺序、提示词、生成/选材来源、截取区间和真实规格；支持排序、替换、预览。结果区区分独立片段与合成成片。

服务端保存固定版本的合成清单：成片 ID、片段 ID/业务任务 ID/结果版本、顺序、裁切范围、画幅适配、目标帧率、声音策略、可选字幕/BGM和导出规格。客户端不能提交任意文件路径、滤镜表达式或命令。实际资源必须通过权限验证和媒体探测。

流程为：需求整理 → 方案/片段计划 → 逐项报价及合计 → 明确确认 → 片段任务 → 核对片段 → 合成任务 → 成片。LangGraph 管理分支、等待、恢复；Celery 处理生成和 FFmpeg；现有业务数据仍是费用、任务和结果权威。当前广告全流程尚未由图驱动，不将新增清单视为完成接入。

首版先做直切、明确裁切、统一画幅/编码/帧率/音频格式，再做受控淡入淡出；不先做复杂特效编辑器。合成总时长按实际片段裁切和转场重叠计算，不把供应商目标时长当探测结果。缺失片段不得静默跳过；用户明确移除才修订合成清单。

## 现有代码复用边界

- API `app/tasks/episode_cut_tasks.py` 已有 FFmpeg concat 段落；抽取无短剧业务依赖的公共媒体工具，不修改原剧情调度或接入旧画布。
- API `app/services/audio_postprocess_service.py` 已有原声混入/替换基础；现有 mix 直接引用 `[0:a]`，无音轨源视频还需补探测/静音支路，不能直接宣称所有视频可用。
- 统一媒体存储、资料权限和任务服务继续复用。不同编码/分辨率不能直接使用现有 `-c copy` 拼接片段，须先探测并规范化。

## 外部项目借鉴，而非整套搬入

- [Editly](https://github.com/mifi/editly)：借鉴 clips/layers/audioTracks 的声明式结构；不直接引入其完整 Node/OpenGL 渲染栈。
- [Remotion 顺序视频](https://www.remotion.dev/docs/videos/sequence)：借鉴按真实时长编排片段的结构；当前 Nuxt + Python/FFmpeg 不为简单拼接新增 React 渲染平台。
- [FFmpeg 官方滤镜](https://ffmpeg.org/ffmpeg-filters.html)：作为 concat、xfade、音频混合的实现依据。先验证本站二进制滤镜能力再开放对应选项。

以上均不是 Oii 内部实现的证据。若未来直接引入第三方包，另核对依赖、维护状态和许可证。

## 后续批次与验收

1. 完成多条独立任务：正式报价/签名、合计确认、现有费用许可、事务性待派发记录、稳定条目请求号和结果恢复；不通过循环两个收费接口冒充原子批次。
2. 增加成片/片段层级合同与轻量合成任务，先用本地测试媒体验收，无需付费生成。
3. 接列表式片段编辑、播放与合成结果；旧会话继续原路径，禁止猜测后自动合成历史结果。
4. 合成失败只重合成；生成失败只重新报价并重试选中片段。更换 BGM 不重生视频；已成功条目不重复扣费。未知采购状态先对账。

必须验证：多条非二条、单片多段、多片多段、排序/裁切、无音轨、混合分辨率/帧率、时长及音画同步、刷新/断线/API及 Worker 恢复、并行确认和过期报价。付费生成另取具体模型及预算授权。本轮未完成真实付费端到端、合成浏览器和 Worker 故障恢复验收。
