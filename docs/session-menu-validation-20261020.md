# 最近项目菜单修复验证

## 最新用户要求覆盖下文历史方案

- 改为Nuxt UI原生`UPopover mode="hover"`，open-delay=0、close-delay=200；由HoverCard管理触发器与内容区域，不恢复业务侧计时器。
- 删除“继续对话”菜单项；修改封面、收藏、删除普通会话因未接入暂不显示，不再显示灰色占位。已有短剧删除与会话重命名保持原业务边界。
- 249项测试通过。真实页面通过键盘聚焦触发器观察到原生悬停浮层，仅有可用操作；截图`session-menu-native-hover-final.png`。实际指针跨区域仍需人工复核。

## 先前方案记录（已被以上要求替代）

- 原实现将鼠标悬停计时器与Dropdown组件开关混用，指针离开触发器后可能在菜单内被延迟关闭；第一轮保留悬停的修复经用户反馈仍失败，不作为通过记录。
- 最终方案删除悬停开关、关闭计时器和手动焦点控制，使用Nuxt UI UDropdownMenu非模态点击菜单。组件原生处理键盘、选中、外部点击和Esc；展开时通过行状态保持三点可见、向父浮层发送交互保持状态。
- 菜单按统一14px文字、18px图标、38px行高整理。移动到文件夹、添加到剧本不显示。修改封面、收藏和删除普通会话暂无接口，禁用而不伪造保存；短剧删除复用现有接口与LivDialog确认，保留关联会话和独立作品。
- 249项自动测试通过，日志`.codex-runtime/session-menu-tests.log`。包含模板编译、禁用项与无悬停计时器回归；删除接口未在真实数据上调用。
- 真实浏览器在已有登录页面验证点击展开、菜单内方向键切换、菜单保持可见以及Esc最终关闭。截图`.codex-runtime/session-menu-component-final.png`。当前浏览器工具不支持直接模拟鼠标移动，因此不把键盘验证称为真实鼠标悬停验收；该场景需用户实际复核。
- UI规范已写入`docs/livliv-ui-spec.md`。未重命名、删除或修改任何真实项目，不提交Git、不部署。
