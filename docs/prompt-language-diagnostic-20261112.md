# 双语提示词与耗时核查（2026-11-12）

## 原因

运行 `970af6b9-0b4c-42fe-95e6-5e077e88757f` 的 `image_plan.items[0].prompt` 为中文，`prompt_translation.text` 为英文，`execution_language` 却为 en。原前端忠实采用该错误标记，导致标题与两段正文反向显示；未发现两段执行文本在落库时互换。原字段说明已有语义但缺少交叉校验，不能仅归因为前端赋值或类型 Schema。

## 修改

- 强化实际模型 Schema 字段说明，明确执行语言属于外层 prompt，提供双向示例。
- 新图片交付在原业务校验边界检查明确字符语言与声明矛盾，返回具体字段、期望语言及修正动作。使用原有限纠正流程，不自行翻译、交换或改写执行文本。
- 历史运行只读显示时，仅明确中英文互译对修正标签；不改历史执行内容、报价与账务。短语、混合或日／韩文不强行猜测。
- 补逐轮模型耗时及输入规模诊断，不保存私人正文。尚未改变模型思考预算或扩大并发，不能声称模型响应已提速。

## 耗时与工具说明

该轮规划耗时 63,817ms，首次文字约 8.5 秒；四轮编排加一次结构化交付，累计输入 87,060 token。原 SSE 约150ms检查一次版本，预览120ms合并；没有证据将一分钟等待归为前端延迟。

- `read_creation_skill` 是注册的授权选择工具；图片助理全文由 Deep Agents 原生 `SkillsMiddleware` 注入，校验实际加载后才显示成功。
- `read_resource` 是注册的受控资源读取工具，用于技能文档引用的方法资源，不是重新读取用户图片。
- `generate_response` 是注册的结构化交付工具，内部再调用一次文本模型写方案；未确认预览逐步显示，最终通过完整校验后才进入费用确认。
- 独立「正在思考」仅是当前模型请求等待状态，不是另一个工具。报价与 Worker 生图分别是业务服务与媒体任务，不属于原生技能读取。

## 最终确认回退修复

该轮 `review_required=false`，报价就绪后因有效期结束，旧 UI 隐藏费用卡而回退到「确认方案」。并非模型要求再次审核，也不是双语修正导致。按最新交互约定，最终卡主操作始终为「确认执行」；可见、未修改的待确认卡自动更新过期报价，不提供重新核算入口。每份旧报价自动尝试一次，失败保留错误并阻止旧价执行；在途原提交继续走原请求恢复。自动更新不调用准备／生成提交，不移除后台报价有效期保护。
