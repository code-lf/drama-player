## 本轮范围

合并处理问答顺序、图片理解记录、内部修正展示，以及商品主图单图合同误拒。沿用 Deep Agents 0.7.32、原素材权限、任务输入、报价与费用确认；不扩展剪辑工作台、短剧，不采购媒体、不提交 Git 或部署。

## 根因与改动

| 问题 | 已实现的处理 | 保留边界 |
| --- | --- | --- |
| 回答卡跑到后续分析下方 | 服务端为回答持久化 `timeline_id`，后续事件带同源关联；当前与历史共用时序投影，在后续分析前插入答案卡 | 旧记录只在可信提问边界恢复顺序，无可信证据不伪造时间线 |
| 发图后没有理解记录 | 实际多模态请求发出才出现“理解图片”进行中，完整响应后更新原位置；问题卡补图和输入框发图走同一适配器 | 上传成功、系统预载不冒充理解成功；异常、断流、拦截不打勾 |
| 两次“整理方案／需修正”像重复执行 | 内部交付开始和拒绝记录保留审计，不作为反复的公开工具行；无公开正文时使用原“正在思考”；最终失败保留一处 | 模型实际公开说明仍保留，成功不靠假动画补造；没有删除内部校验 |
| 一张主图用完调用预算 | 单图 Schema 不再携带不适用的 `media_plan/image_plan/creative_plan`，不强迫填 null；按本轮合同反馈前次字段错误供有限修正 | 不增加 6 次编排／2 次交付上限；结构、目录、素材版本、权限、报价和执行幂等仍校验 |
| 不清楚供应商约束与本地校验谁出错 | 用实际下发的同一份 Schema 做本地 JSON Schema 校验，再走原 Pydantic 业务校验；保存请求序号、Schema/回包指纹、终止分类和脱敏字段错误 | 不保存私人图片、正文、推理或密钥；禁用 Schema 远程引用读取，不做正文语义猜测 |

## 阿里云参数核对

核对 [阿里云结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)：项目走 Chat Completions，`response_format.type=json_schema`，`json_schema.strict=true`，不是只保证合法 JSON 的 `json_object`。当前 Qwen3.7-Plus 支持该模式。

官方支持可选字段从 `required` 省略，null 是类型而不是“可以省略”的同义词。本次保留业务必填列表，不再把所有声明字段强行设为必填。结构化请求不携带 tools，也不携带 `max_tokens`，遵循官方避免截断 JSON 的建议；普通工具编排仍带输出上限。

**预算风险说明**：结构化单次请求没有供应商端 `max_tokens` 硬限制，应用层总输出预算 64000、时间及调用次数限制不变。结构化请求预占全部剩余预算，只有可信 usage 才按实际结算，未知成本不发下一次请求；实际超总预算拒绝应用及后续请求。这是后验保护，不保证供应商单次账单绝不超额，不能对外称为硬扣费上限。

## 图片理解复用与续聊附件补验

本节替代后文“仅展示去重、仍重复发送图片”的历史限制，沿用 Deep Agents、LibraryService 和原运行 JSON，不增加缓存框架或平行任务状态。
