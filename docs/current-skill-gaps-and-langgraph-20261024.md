# 当前技能闭环缺口与 LangGraph 实际职责

## 本次只读核对

数据库当前平台技能67项，均启用、采用Markdown指导模式并有example_spec。plan_type分布为direct52、ad_variants11、product_set3、detail_page1；这些是配置声明，不等于对应执行流程已全部接通或逐项验收。

`creation_run_service.advance`按固定技能版本解析指导文档，加入可用模型/素材边界与专业计划合同；`creation_skill_service`编译生成前后约束。因此并非只把卡片名称发送给模型，但目前许多技能仍主要是专业提示词配方复用通用执行器，不能称67套完整专业代理。

## 什么才算一项技能闭环

按该技能真实交付需要完成：需求及素材收集、专业指导/必要资料读取、方案与规格核对、真实报价和用户授权、业务任务执行、结果交付及必要质量核对、局部失败恢复。简单单图不强制经过识别报告或复杂问卷；复杂套图/详情页不能降为一次单图生成。每项需独立验收记录，示例格式正确不证明输出质量及流程可用。

## 当前阶段未完成清单

1. **67项逐项验收及限制显示**：逐项检查来源、指导、示例、素材、模型/数量/时长合同和结果，不以统一通用提示词或配置项数量代替。未接通完整流程的技能明确展示能力边界。
2. **统一试用预检**：首页/详情/快捷区同一逻辑；手动规格冲突确认、素材与示例一次应用、迟到响应隔离及撤销完整恢复。已有局部保护不等于统一只读服务及全量验收完成。
3. **阶段收集与结构化需求推广**：现有商品主图阶段试点/广告计划链路之外，覆盖合适技能；底部自然输入只更新受影响字段，已确认信息不重问。
4. **专业知识与识别核对**：授权固定文档读取、真实事件、专业风格资料、图中确认/推测/缺失区分及用户纠正；未完成通用闭环，不能显示虚假“已读取”。
5. **套图→详情页→日历**：已有视频条目基础，仍需适配各自条目类型、共享信息、编辑/拆批/报价/结果；不能把plan_type字段视为流程已经实现。多版本广告已有真实成功样例，但不是11项配置均验收。
6. **配乐可选子流程**：上传/资料库/AI三来源、试听选择、选段/音量/原声策略、免费合成及局部重试，复用既有音乐与混音服务，尚未统一打通验收。
7. **剩余105项适配与165项来源清单**：依真实输入产出和所需能力逐项开放，保留未接入原因；不扩展范围外60项，不动短剧。
8. **异常与开放门槛**：原3条未知采购60积分仍待外部对账；真实失败局部重试页面、完整断线恢复及未测布局需补验；全局收费批次仍关闭。新两条真实成功不能替代未知态处理。

优先顺序：先把已开放技能的正确性、边界、预检和阶段合同做实；再知识/识别与套图，继而详情页/日历/配乐，最后继续来源适配。三条外部采购对账是独立阻塞，不应阻止不采购的框架和内容开发。

## LangGraph 已实际做到什么

`creation_flow_graph.py`使用StateGraph、PostgresSaver、interrupt和Command。当前根图主要是“等待明确命令→执行服务端登记业务→保存阶段→继续等待”的受控命令循环，并不是每项技能已拥有完整的策划/识别/质检专家图。

- 已固定运行引擎、图/技能版本及命令修订；持久化等待位置。
- 收到明确命令才推进规划、编辑、核价、准备授权、确认、读取结果及成片后期。
- 检查点与原业务记录核对恢复；原任务/费用/执行许可仍由业务服务管理。
- 新批次真实两条视频到三份成片，经v2根图到composition_results/sequence16。
- 阶段收集图、媒体/合成子图已有专项恢复测试，不意味着全部67项自动接入。

LangGraph不提供电商知识、不自动读取资料库、不生成视频、不改善供应商耗时、不自动实现幂等扣费，也不自动赋予全量长期记忆。幂等/权限/费用授权依赖本站实现；Celery负责耗时任务，FFmpeg负责真实合成。LangChain与LangGraph不是同一层：本项目本轮核心引入的是LangGraph编排，而非整套LangChain工具代理。
